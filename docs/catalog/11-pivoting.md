# 11 — Pivoting

## Concept

Pivoting transforms distinct values in one or more "pivot columns" into dynamically generated column
groups, with each group containing value columns aggregated by `aggFunc`. It is an **Enterprise**
feature gated by `PivotModule`. Pivoting only works with the Client Side Row Model (CSRM) and the
Server Side Row Model (SSRM, see [SSRM Pivoting](https://www.ag-grid.com/javascript-data-grid/server-side-model-pivoting/) docs).

Key concepts:

- **Pivot mode** — `pivotMode=true` activates the pivot rendering pipeline. When pivot mode is
  active and at least one column has `pivot=true`, the grid generates secondary (pivot result)
  columns from distinct key values.
- **Pivot columns** — `ColDef.pivot` / `pivotIndex` mark which columns produce pivot keys. Multiple
  pivot columns create a nested column group hierarchy.
- **Value columns** — columns with `aggFunc` are the value columns; each pivot key group contains
  one value column per value definition.
- **Primary vs secondary columns** — primary columns are the user-defined `ColDef` array; secondary
  (pivot result) columns are generated by the grid. Primary columns may be hidden in pivot mode
  (the grid swaps them out); the generated secondary columns are accessible via
  `getPivotResultColumns`.
- **Pivot totals** — `pivotColumnGroupTotals` and `pivotRowTotals` add automatically calculated
  total columns/rows within the pivot structure.
- **Aggregation** — pivot builds on the aggregation pipeline in `10-aggregation.md`. Each pivot
  result column inherits `aggFunc` from the corresponding value column.
- **Chart integration** — pivot results can feed directly into an AG Charts pivot chart. See
  `24-charts-and-sparklines.md` for chart-from-pivot integration.

## Configuration surface

### ColDef — pivot properties

| Option | Type | Default | Tier | Description |
|--------|------|---------|------|-------------|
| `pivot` | `boolean \| null` | `undefined` | Enterprise | Set `true` to pivot by this column's values. Requires `PivotModule` and `pivotMode=true`. |
| `initialPivot` | `boolean` | `undefined` | Enterprise | Same as `pivot` but applied only on first column creation; ignored on updates. |
| `pivotIndex` | `number \| null` | `undefined` | Enterprise | Order of this column in the pivot hierarchy when multiple columns are pivoted. |
| `initialPivotIndex` | `number` | `undefined` | Enterprise | Same as `pivotIndex` but initial-only. |
| `enablePivot` | `boolean` | `false` | Enterprise | Allows user to drag this column into the pivot panel via the GUI. Does not block API pivoting. |
| `pivotComparator` | `PivotComparatorFunc` | `undefined` | Enterprise | Comparator `(valueA: string, valueB: string) => number` that controls the order of generated pivot column groups. Values are always strings (pivot keys). |

### GridOptions — pivot properties

| Option | Type | Default | Tier | Description |
|--------|------|---------|------|-------------|
| `pivotMode` | `boolean` | `false` | Enterprise | Activates pivot rendering mode. When `true` and pivot columns are defined, the grid generates secondary columns. |
| `pivotPanelShow` | `'always' \| 'onlyWhenPivoting' \| 'never'` | `'never'` | Enterprise | Controls visibility of the pivot drag-and-drop panel. Requires `RowGroupingPanelModule`. Initial-only. |
| `pivotMaxGeneratedColumns` | `number` | `-1` | Enterprise | Maximum number of generated pivot columns before the grid halts and fires `pivotMaxColumnsExceeded`. `-1` for no limit. |
| `pivotDefaultExpanded` | `number` | `0` | Enterprise | Number of pivot column group levels to expand by default. `-1` expands all. |
| `pivotColumnGroupTotals` | `PivotColumnGroupTotals` | `undefined` | Enterprise | Adds total columns within each pivot column group. Values: `'before'` (left of the group) or `'after'` (right). |
| `pivotRowTotals` | `PivotRowTotals` | `undefined` | Enterprise | Adds total value columns for each value column across all pivot key groups. Values: `'before'` or `'after'`. |
| `pivotSuppressAutoColumn` | `boolean` | `false` | Enterprise | Prevents the grid from automatically inserting the group column in pivot mode. Useful for SSRM or Viewport Row Model where the developer controls all columns. Initial-only. |
| `suppressExpandablePivotGroups` | `boolean` | `false` | Enterprise | Makes pivot column groups fixed (not expandable/collapsible by the user). Initial-only. |
| `removePivotHeaderRowWhenSingleValueColumn` | `boolean` | `false` | Enterprise | Omits the value-column header row when only one value column is defined. |
| `processPivotResultColDef` | `ProcessPivotResultColDef<TData>` | `undefined` | Enterprise | Callback `(colDef: ColDef) => void` called for each generated pivot result leaf column, allowing mutation of its definition before the grid renders it. |
| `processPivotResultColGroupDef` | `ProcessPivotResultColGroupDef<TData>` | `undefined` | Enterprise | Callback `(colDef: ColGroupDef) => void` called for each generated pivot result column group definition. |

## API methods

| Method | Signature | Tier | Description |
|--------|-----------|------|-------------|
| `isPivotMode` | `() => boolean` | Enterprise | Returns `true` if pivot mode is currently active. |
| `setPivotColumns` | `(colKeys: ColKey[]) => void` | Enterprise | Replaces the current pivot columns with the given set. |
| `addPivotColumns` | `(colKeys: ColKey[]) => void` | Enterprise | Adds columns to the pivot definition. |
| `removePivotColumns` | `(colKeys: ColKey[]) => void` | Enterprise | Removes columns from the pivot definition. |
| `getPivotColumns` | `() => Column[]` | Enterprise | Returns the current pivot columns. |
| `getPivotResultColumn` | `<TValue>(pivotKeys: string[], valueColKey: ColKey) => Column<TValue> \| null` | Enterprise | Looks up a generated pivot result column by its pivot key path and value column. |
| `getPivotResultColumns` | `() => Column[] \| null` | Enterprise | Returns all currently generated pivot result columns, or `null` when not in pivot mode. |
| `setPivotResultColumns` | `(colDefs: (ColDef \| ColGroupDef)[] \| null) => void` | Enterprise | Manually sets the secondary (pivot result) column definitions, bypassing the grid's auto-generation. Used with SSRM or when `pivotSuppressAutoColumn=true`. |
| `setValueColumns` | `(colKeys: ColKey[]) => void` | Enterprise | Replaces the value columns (aggregated columns) used in the pivot. |
| `addValueColumns` | `(colKeys: ColKey[]) => void` | Enterprise | Adds value columns to the pivot. |
| `removeValueColumns` | `(colKeys: ColKey[]) => void` | Enterprise | Removes value columns from the pivot. |
| `getValueColumns` | `() => Column[]` | Enterprise | Returns the current value columns. |

## Events

| Event | Payload | Tier | Fires when |
|-------|---------|------|-----------|
| `columnPivotModeChanged` | `ColumnPivotModeChangedEvent {}` | Enterprise | `pivotMode` is toggled on or off. |
| `columnPivotChanged` | `ColumnPivotChangedEvent { column: Column \| null; columns: Column[] \| null; source: ColumnEventType }` | Enterprise | A column is added to or removed from the pivot column set. |
| `columnValueChanged` | `ColumnValueChangedEvent { column: Column \| null; columns: Column[] \| null; source: ColumnEventType }` | Enterprise | A column is added to or removed from the value (aggregation) column set. Also fires in row-grouping context; see `10-aggregation.md`. |
| `pivotMaxColumnsExceeded` | `PivotMaxColumnsExceededEvent { message: string }` | Enterprise | The number of generated pivot columns exceeds `pivotMaxGeneratedColumns`. The grid halts column generation and fires this event. |
| `gridColumnsChanged` | `{}` | Community | The internal column list changes, including after pivot result columns are generated or removed. |

## Behaviors / interactions

**Pivot mode activation:** Setting `pivotMode=true` alone does not pivot anything; at least one
column must have `pivot=true` (or be added via `addPivotColumns`). When active, the grid replaces
the primary column set with the auto-generated secondary columns. Primary columns remain accessible
in the column tool panel but are hidden from the grid body.

**Pivot key ordering:** By default, pivot key values are sorted using the default string comparator.
Use `pivotComparator` on the pivot column's `ColDef` to apply a custom order (e.g. month names,
custom sort buckets). The comparator always receives string keys.

**`processPivotResultColDef` / `processPivotResultColGroupDef`:** These callbacks receive a mutable
`ColDef` or `ColGroupDef` object immediately before the generated columns are inserted. They can
override any property (e.g. `headerName`, `cellClass`, `width`). They are called each time the grid
regenerates pivot columns (e.g. when data changes).

**Pivot total columns (`pivotColumnGroupTotals`):** When set to `'before'` or `'after'`, an extra
aggregate column is appended to (or prepended within) each pivot key group. The aggregate function
comes from the value column's `aggFunc`.

**Pivot row totals (`pivotRowTotals`):** Inserts a special "total" column outside the pivot key
groups — one for each value column — containing the row-level aggregate across all pivot key groups.

**`removePivotHeaderRowWhenSingleValueColumn`:** When there is only one value column, the intermediate
header row showing the value column name is unnecessary. Setting this to `true` flattens the header,
reducing its height by one level.

**SSRM pivoting:** The server-side row model supports pivoting but requires the server to compute
pivot results. Use `setPivotResultColumns` to inject the server-supplied secondary column definitions.
See the AG Grid SSRM Pivoting documentation for the full request/response protocol.

**Pivot and aggregation interaction:** Pivot builds directly on the aggregation pipeline
(`10-aggregation.md`). Each generated pivot result column inherits the `aggFunc` from the
corresponding value column definition. `suppressAggFuncInHeader` applies within pivot result column
headers as well.

**Chart integration:** Pivot mode and AG Charts integrate via the `pivotChart` creation flow. When
chart ranges are created while `pivotMode=true`, the chart reads from the pivot result columns.
See `24-charts-and-sparklines.md` for detailed chart-from-pivot usage.

**`suppressExpandablePivotGroups`:** When `true`, generated pivot column groups cannot be
collapsed/expanded by the user. This avoids the confusing UX where pivot group headers appear
interactive but collapsing them hides data.

## Canvas-port implications

- Pivot requires a two-phase column pipeline: (1) derive distinct key values from the data to
  determine secondary column definitions, then (2) run the aggregation pipeline using those
  secondary columns. The canvas engine must support dynamic column sets that are not known until
  data arrives.
- `processPivotResultColDef` / `processPivotResultColGroupDef` mutate generated column definitions.
  The canvas column-definition system must support a late-mutation callback hook in the same
  position.
- `getPivotResultColumns` / `setPivotResultColumns` form the primary contract for SSRM pivot
  integration. The canvas port must implement these API methods with equivalent semantics.
- `pivotMaxGeneratedColumns` is a safeguard against pathological data (many distinct values).
  Implement a column-count check during secondary column generation; fire an equivalent event and
  halt when the limit is exceeded.
- Pivot column group totals and row totals require the canvas renderer to distinguish injected
  total columns from regular data columns, so they can be styled differently (e.g. bold, shaded
  background).
- The pivot key ordering (`pivotComparator`) must be applied during secondary column generation,
  before any column definitions are passed to the layout engine.
- Cross-reference: `10-aggregation.md` for aggregation pipeline details; `24-charts-and-sparklines.md`
  for pivot-chart integration; `02-column-model.md` for primary/secondary column model distinction.
