```ts
export class EditJournal {
  constructor(opts: {
    applyPatches: (patches: CellPatch[], direction: 'forward' | 'undo') => void;  // injected applier; journal NEVER touches a grid
    getHistorySettings: () => DataChangeHistorySettings;   // read LIVE on every record (maxEntries/suspended can change)
    now?: () => number;          // default () => 0 (Date-free)
    nextId?: () => string;       // default internal counter 'e1','e2',…
    monitorLimit?: number;       // default 100
  });
  record(input: { source: EditSource; label: string; patches: CellPatch[] }): EditJournalEntry | null;
  undo(): EditJournalEntry | null;
  redo(): EditJournalEntry | null;
  undoEntry(entryId: string): EditJournalEntry[];   // STUB in this task (see Interfaces); cascade body lands Task 3
  canUndo(): boolean; canRedo(): boolean;
  entries(): readonly EditJournalEntry[];           // past copy, oldest→newest
  monitorEntries(): readonly EditJournalEntry[];    // audit copy, oldest→newest
  subscribe(listener: () => void): () => void;      // fires after every state mutation; returns unsubscribe
}
```

Pinned semantics:
  - `record` returns `null` (and stores NOTHING anywhere — no past, no monitor, no future-clear, no listener fire) when `shouldRecord(source, getHistorySettings())` is false OR `patches.length === 0`. Otherwise: build the entry (id via `nextId`, timestamp via `now`), push onto `past` (trim OLDEST while `past.length > maxEntries` — maxEntries read live from `getHistorySettings()` at this moment), CLEAR `future`, append to `monitor` (trim oldest past `monitorLimit`). The monitor gets every recorded entry at record time, so entries that later fall off the undo stack are retained there — that is the monitor's purpose (audit trail decoupled from undo cap, recon A.1).
  - `undo`: pop newest from `past` → `applyPatches(entry.patches, 'undo')` → push onto `future` → notify listeners → return entry; `null` when `past` empty (no applier call, no listener fire). `redo` is the mirror image with `'forward'`.
  - Suspended ≠ disabled: a suspended journal rejects new `record`s but `past` stays intact and `undo`/`redo` still work (spec §3.5).
